# StayPilot Constitution v2.0

## Vision
StayPilot is an AI-native Hospitality Intelligence Platform that becomes the operating system for boutique hospitality.

## Mission
Build the world's most trusted AI Operating System for hospitality businesses.

## Core Values
- Guest Experience First
- AI-First, Not AI-Added
- Workflow-First
- Platform Thinking
- Long-term Maintainability

## Engineering Principles
- Domain-Driven Design
- Event-Driven Architecture
- API-First
- Configuration over Customization
- Security by Design
- Observability by Default
- Human-in-the-Loop
- Explainable AI

## Architecture Principles
- Modular architecture
- Bounded Contexts
- Shared Hospitality Brain
- Knowledge Graph
- AI Agent Framework
- CQRS where beneficial
- Clean Architecture

## AI Constitution
- AI recommends before it automates.
- Every recommendation includes rationale.
- High-risk actions require approval.
- Agents use tools—not direct database writes.
- Shared context is the source of AI reasoning.

## Security
- RBAC
- Audit logs
- Encryption
- Least privilege
- Tenant isolation

## Documentation Standards
- Every feature requires PRD, ADR (if architectural), API spec, DB design, AI design, test plan and changelog updates.

## Development Lifecycle
- Research → PRD → Architecture → Database → API → UI → AI → Testing → Documentation → Release

## Definition of Done
- Business requirements approved
- Tests pass
- Docs updated
- Observability added
- Security reviewed

## Roadmap
- Phase 1: Hospitality Research
- Phase 2: Product Design
- Phase 3: Architecture
- Phase 4: MVP
- Phase 5: AI Workforce
- Phase 6: Marketplace

## Amendment Process
Changes require architecture review, ADR, version increment and approval.

## Non-Negotiable Rules
- Business domains own business rules.
- Everything important emits events.
- AI never becomes the system of record.
- Every automation is explainable.
- Every AI action is auditable.
- Documentation evolves with code.

## North Star
Our resort runs on StayPilot.
